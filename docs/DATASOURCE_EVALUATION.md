# 实时岗位数据源评估(替代静态数据集)

> 目的:为「把 backup(GitHub 静态数据集)替换为实时采集」提供选型依据。
> 评估视角:本项目的三个硬约束 ——
> ① 需求 3.2 边界:不逆向、不绕过验证码;
> ② 现有 ETL 面向**中文、中国大陆、数据分析/数据科学岗**的字段语义(城市/薪资/学历/经验枚举、jieba 技能词);
> ③ 接入成本:新增 adapter 文件 + 在 `adapter_factory.py` 注册 `--source` 即可,`pipeline`/`checkpoint`/幂等写入全部复用。

---

## 0. 先说结论

- **没有"免费好用的中文招聘实时 API"**。智联/BOSS/拉勾/猎聘的开放平台 API 已基本停止对外开放,仅限企业资质申请;公开渠道拿不到 key。
- 中文主流招聘平台的**网页爬取普遍被强反爬保护**(BOSS:App 签名+验证码;51job:阿里云 WAF,本项目已实测;猎聘:风控强),按需求 3.2 边界判定不可用。
- 相对可行的是:**大厂招聘官网公开接口 > 国聘网/人社部 > 牛客/应届生求职网 > 海外免费 API(英文)**。
- 各源接口字段、端点存在时效性,**接入前必须现场实测**(写 adapter 时验证),本文档结论以「评估日」为限。

评估日期:2026-02(与 51job W1 验证同批次)。

---

## 1. 候选源分档评估

### A 档:大厂招聘官网公开接口 —— 最推荐

代表:字节跳动(`jobs.bytedance.com`)、腾讯(`careers.tencent.com`)、阿里、华为、美团等自建招聘站点。

| 维度 | 评价 |
|---|---|
| 合规性 | 高:公开招聘信息,低频访问属合理使用;无需逆向/绕过验证码 |
| 反爬强度 | 低~中:自研站点多为公开 JSON 接口,仅需常规 UA/限速/重试(项目已具备) |
| 数据质量 | 高:字段规范(城市/类别/经验/学历/薪资区间),文本真实 |
| 实时性 | 高:直接反映在招岗位,可做增量批次 |
| 覆盖面 | **低:只覆盖大厂,不能代表全市场**(与现有 7,387 条多平台数据的市场语义不同,需在报告中声明样本口径变化) |
| 维护成本 | 中:接口端点偶有变动,需实测;建议固定大厂白名单 + checkpoint 续爬 |
| 字段适配 | 各厂字段名不同,需 adapter 内统一映射;薪资多为区间,现有 `salary.py` 归一化可直接复用 |

接入要点:`cities × categories` 关键词组合可退化为「城市/类别筛选项直取」,无需关键词搜索,接口更简单。

### B 档:国聘网 `iguopin.com` / 各地人社局 —— 合规性好,偏国企

| 维度 | 评价 |
|---|---|
| 合规性 | 高:人社部指导的官方平台,公开数据 |
| 反爬强度 | 低:公开列表页/接口,限速即可 |
| 数据质量 | 中:字段完整但偏国企/事业单位口径(城市/学历/专业要求) |
| 覆盖面 | 偏国企央企/事业单位,私企互联网岗位少;与现有"数据科学/算法"画像错位明显 |
| 维护成本 | 低~中 |

### C 档:牛客网 / 应届生求职网 —— 贴合学生项目语义

| 维度 | 评价 |
|---|---|
| 合规性 | 中:公开信息,但站点条款需自行确认 |
| 反爬强度 | 中:较主流招聘 App 弱,仍可能遇到登录墙/滑块 |
| 数据质量 | 中:校招/实习岗位多,岗位描述质量参差 |
| 语义契合 | **高:本项目面向"数据分析/数据科学实习+秋招"**,校招源天然对口 |
| 维护成本 | 中 |

### D 档:海外真·免费 API —— 稳定但英文/欧美

| 源 | 免费额度 | 说明 |
|---|---|---|
| Remotive / RemoteOK | 全免费,无需 key | 远程岗位 API,文档规范、稳定 |
| Adzuna / Jooble | 注册免费 key,有限额度 | 欧美市场为主 |
| JSearch(RapidAPI) | 免费层 | 聚合多个平台,但免费层限制大 |

- 优点:接口规范、稳定、合规,真正"开箱即用"的免费 API。
- 缺点:**岗位为英文/欧美市场**,与现有中文 ETL(薪资归一人民币口径、城市枚举、jieba 技能词、XGBoost 文本特征)几乎全链路不匹配,需新增英文清洗/建模分支,工作量大。
- 定位:仅当「练 API 集成」优先于「中文数据」时考虑,或作为技术演示的补充源。

### E 档:主流平台网页爬取 —— 明确不建议

| 平台 | 反爬现状(截至评估日) | 结论 |
|---|---|---|
| 51job | 阿里云 WAF JS 挑战(全端点,含移动端),本项目已实测 | 不可用,保留骨架 `src/crawler/job51.py` |
| BOSS 直聘 | App 签名、滑块验证码、风控封禁 | 不可用(绕过即违反需求 3.2) |
| 智联/猎聘 | 登录墙 + 签名 + 风控 | 不可用 |
| 拉勾 | 接口签名校验 | 不可用 |

### F 档:准实时替代方案 —— 稳定但不"实时"

- GitHub 上存在定期更新的招聘数据集仓库(如现用的 `Rayair019/Job-posting-data` 系)。
- 可写一个 `--source dataset-daily` adapter:按计划任务拉取最新版数据集 → 走现有 backup 字段映射 → 幂等增量入库。
- 优点:零反爬风险、ETL 完全复用;缺点:不是真实时,数据滞后于数据集更新周期。
- 适合作为「实时源 404 时的自动兜底」与现有 `backup` 互补。

## 2. 字段映射差异提示(接入任何源前先看)

现有 `jobs` 表核心字段:title / company / city / category / salary_min / salary_max / education / experience / industry / job_desc / source_id。

各候选源与现有枚举的差异:

| 字段 | 大厂官网 | 国聘网 | 海外 API | 现有 backup |
|---|---|---|---|---|
| 城市 | 中文,规范 | 中文,规范 | 英文城市名 | 中文 |
| 薪资 | 区间/面议 | 区间/面议 | 外币+币种字段 | 区间 |
| 学历/经验 | 自研枚举(需映射) | 政府口径(本科及以上等) | 无/简略 | 已有归一化 |
| 岗位类别 | 无现成分类,需按关键词/标题打标 | 专业要求字段 | 无 | 数据集自带 |
| JD 文本 | 完整,质量高 | 完整 | 完整(英文) | 完整 |

结论:大厂官网与国聘网离现有 schema 最近;海外 API 最远(需新增币种换算与英文 NLP 分支)。

## 3. 推荐落地路径(供你决定后执行)

1. **首选**:实现 A 档「大厂招聘官网」adapter(白名单 2~3 家,如字节+腾讯),现场实测接口 → 字段映射 → 注册 `--source bigtech` → 与 backup 并列跑通增量。
2. **兜底**:保留 backup 数据集;如需"自动更新"再补 F 档 dataset-daily。
3. **语义补充**(可选):C 档牛客/应届生,补校招实习岗位,与项目"实习+秋招"定位最贴合。
4. **不建议**:E 档主流平台硬爬;D 档海外 API 仅作技术演示。

> **已落地(2026-02)**:B 档国聘网(`--source iguopin`,`gp-api.iguopin.com/api/jobs/v1/list` 公开接口,`job_name` 标题搜索)
> 与 C 档牛客网(`--source nowcoder`,`nowpick.nowcoder.com/u/job/search` 公开接口)已实现 adapter 并接入前端
> 「数据源」下拉框;接口端点与字段映射见 `src/crawler/iguopin.py` / `nowcoder.py` 注释。

## 4. 合规与风险声明

- 所有爬取遵守本项目需求 3.2(不逆向、不绕过验证码),低频限速(项目已有 `delay_min/max`、重试退避)。
- 大厂官网接口端点、字段随时可能变动,adapter 需内置"接口变更熔断"(返回结构校验失败 → 明确告警而非静默坏数据),可复用 `monitor.py` 健康监控。
- 数据仅作市场趋势参考,不二次分发。
